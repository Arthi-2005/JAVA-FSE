# Exercise 03 — Sprint Planning

## Objectives

- Learn how to write user stories
- Estimate work using story points
- Create a sprint backlog

## User Stories

A user story describes a feature from the user's perspective.

**Format:** `As a [role], I want [feature] so that [benefit].`

**Example:** "As a customer, I want to reset my password so that I can regain access to my account."

## Acceptance Criteria

Conditions that must be met for the story to be considered done.

**Example for password reset:**
- User enters registered email
- System sends reset link to email
- Link expires after 1 hour
- User can set a new password

## Story Points

Story points measure relative effort, not hours. Common estimation scales:

- **Fibonacci:** 1, 2, 3, 5, 8, 13, 21
- **T-shirt sizes:** XS, S, M, L, XL

## Sprint Planning Steps

1. **Capacity Planning**: Calculate how many hours the team has available.
2. **Backlog Refinement**: Product Owner presents top-priority stories.
3. **Estimation**: Team estimates each story in story points.
4. **Commitment**: Team selects stories they can complete in the sprint.

## Practice Tasks

1. Write user stories for a library management system (borrow books, return books, search catalog, pay fines).
2. Estimate each story using Fibonacci story points.
3. Create a sprint backlog for a 2-week sprint assuming the team can handle 20 story points.
