# Exercise 01 — Agile vs Waterfall

## Objectives

- Understand the difference between Waterfall and Agile methodologies
- Identify when to use each approach
- Learn the Agile Manifesto values

## Concepts

### Waterfall Model
- Sequential phases: Requirements → Design → Implementation → Testing → Deployment
- Each phase must be completed before the next begins.
- Good for projects with fixed, clear requirements.
- Hard to accommodate changes once development starts.

### Agile Model
- Iterative and incremental development.
- Requirements can evolve throughout the project.
- Working software is delivered in short cycles (sprints).
- Customer feedback is incorporated continuously.

## Comparison Table

| Aspect | Waterfall | Agile |
|--------|-----------|-------|
| Requirements | Fixed at start | Evolving |
| Delivery | Single final release | Frequent small releases |
| Customer involvement | At start and end | Throughout the project |
| Change management | Difficult | Easy to adapt |
| Testing | At the end | Continuous |
| Documentation | Heavy | Minimal |
| Project size | Large, complex | Small to medium teams |

## Agile Manifesto (2001)

1. **Individuals and interactions** over processes and tools
2. **Working software** over comprehensive documentation
3. **Customer collaboration** over contract negotiation
4. **Responding to change** over following a plan

## Practice Tasks

1. Think of a project you've worked on. Would Agile or Waterfall have been better? Why?
2. Write a short paragraph explaining why "responding to change" is important in software development.
3. List 3 scenarios where Waterfall might be better than Agile.
