# Agile vs Waterfall — Comparison Analysis

## Scenario: Library Management System

### Waterfall Approach

```
Requirements ──> Design ──> Implementation ──> Testing ──> Deployment

All requirements gathered upfront (months 1-2)
System architecture designed (month 3)
All features coded (months 4-8)
Full system testing (month 9)
Deployment (month 10)
```

**Risks:** If user requirements change after month 2, the entire plan breaks.

### Agile Approach

```
Sprint 1 ──> Sprint 2 ──> Sprint 3 ──> Sprint 4 ──> Sprint 5

Sprint 1: Book search + view catalog (delivered week 2)
Sprint 2: Borrow books + return books (delivered week 4)
Sprint 3: User authentication + fines (delivered week 6)
Sprint 4: Admin dashboard + reports (delivered week 8)
Sprint 5: Notifications + email integration (delivered week 10)
```

**Benefits:** Users see working software after 2 weeks. Changes can be made between sprints.

## When to Use Each

| Waterfall | Agile |
|-----------|-------|
| Fixed-price contracts | Projects with evolving requirements |
| Regulated industries (healthcare, aviation) | Startups and product development |
| Small, simple projects | Large, complex projects |
| When requirements are well-understood | When requirements are uncertain |
